# Breadth checklist

Every item gets a verdict in the report: **fixed**, **proposed**, **not applicable** (with the reason), or **left to the user** (with the reason). "Not on the slowest chain" is not a reason: under concurrency limits, waste anywhere delays someone's run, and the slowest chain changes as soon as it is fixed.

Items 1–10 adapt the widely shared 10-point CI prompt by @HiTw93; the rest come from the cases in this skill's evaluation.

| #   | Check                                          | How to check                                                                                                                                                                           | Watch out for                                                                                                                                           |
| --- | ---------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1   | Superseded PR runs are cancelled               | `concurrency` with `cancel-in-progress` on PR events                                                                                                                                   | Never cancel default-branch runs; give each its own group (`run_id`) and include the workflow name                                                      |
| 2   | Changes that need no suite skip it             | Count docs-only commits; is there a `changes` job or path gate?                                                                                                                        | Workflow-level `paths` filters leave required checks pending; prefer a `changes` job plus skipped jobs plus a gate job. Find tests that read docs first |
| 3   | Dependency caches on, keyed on the lockfile    | `setup-*` `cache:`, `actions/cache` keys                                                                                                                                               | A big cache (pnpm store, Go modules) saved by one owner job, restored by the rest; PR-scoped saves crowd the 10 GB limit                                |
| 4   | Build and tool state caches are fresh          | Compiler caches (Go build, ccache, sccache), task runners (Turbo, Nx, Gradle), linter caches (`eslint --cache --cache-strategy content`: mtime breaks on checkout), test-result caches | A key that never changes is frozen; key on the commit and restore by prefix. Check the tool's own log line saying it used its cache                     |
| 5   | Tools are downloaded, not compiled             | `go install`, `cargo install`, `npm i -g`, `cabal install`, `pip install --no-binary`                                                                                                  | A pinned version may have no prebuilt binary; cache the built binary instead                                                                            |
| 6   | Local second build is near-instant             | Build twice in a row locally if possible                                                                                                                                               | A Dockerfile copying the whole repo before installing dependencies; build scripts watching missing files                                                |
| 7   | Independent jobs run in parallel               | `needs` edges whose upstream outputs and artifacts are unused                                                                                                                          | A `needs` that only orders jobs delays every downstream start                                                                                           |
| 8   | OS-independent work runs on Linux              | Lint, format, audit, codegen checks on macOS or Windows                                                                                                                                | Free accounts get few concurrent macOS runners, shared across all workflows                                                                             |
| 9   | Work is not repeated across jobs or steps      | Same build, install, codegen, typecheck or lint in several jobs; coverage traced on every matrix leg but uploaded from one                                                             | Merging jobs can lengthen the critical path; dedupe instead                                                                                             |
| 10  | The longest suite is split, balanced           | After the depth pass: is one job's work far above its setup?                                                                                                                           | The union of shards equals the original list; check names change                                                                                        |
| 11  | Checkouts fetch what they need                 | `fetch-depth: 0`, `submodules: true`                                                                                                                                                   | Versioning tools need tags; submodules shallow plus `--jobs`                                                                                            |
| 12  | Docker builds reuse layers                     | Manifests copied before source; `.dockerignore`; `cache-from`                                                                                                                          | Multi-platform builds listing a platform twice                                                                                                          |
| 13  | Test runners use the parallelism they claim    | Worker counts in logs vs runner cores; serial settings in config; `ctest` without `-j`, `make` without `-j`                                                                            | Turning on parallelism or turning off isolation is not equivalent; prove the same names and results over repeated runs                                  |
| 14  | Per-test setup is not redone needlessly        | Clients, apps, servers, databases or static scans built per test or per request in shared helpers; e2e traces and videos recorded for every test; tool lookups per test                | Read the slowest test files' helpers, not only the tests                                                                                                |
| 15  | OS and disk overhead are measured, not guessed | Windows TEMP and caches on the slow system disk; cache unpack time; antivirus                                                                                                          | Changes need log evidence; do not default to turning off security software                                                                              |
| 16  | Every job has a timeout                        | `timeout-minutes`                                                                                                                                                                      | A hung job bills up to 6 hours                                                                                                                          |
