## 2. 4-Quadrant Defense Matrix

| Quadrant                                                                     | Design & Test Assertion                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                           |
| ---------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **1. Legacy server missing optional fields**                                 | `OrchestrationV2Subagent.usage`, `TurnTokenUsage.requestCount`, and `TurnTokenUsage.costUsd` are all `Schema.optional(...)`. Legacy snapshots without these fields decode cleanly; UI omits `Requests` when no turn reports `requestCount`, omits per-subagent context bars when `contextTokens`/`contextWindow` are absent, and falls back cleanly to reference pricing or `–` without ever fabricating `$0`.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    |
| **2. Async / partial frame regression**                                      | `OmpSubagentTracker`, `ClaudeAdapterV2`, `ProjectionStore`, and `orchestrationV2Projection` preserve existing `subagent.usage` when a later update (e.g. `async-result` completion text or status transition) omits `usage` or sends empty/zero fields, preventing metrics from flashing back to `0` or disappearing on completion.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                               |
| **3. Anti-double-count isolation (cost, tokens, subagents, parallel tools)** | (a) **Session cost**: prefer sum of per-turn `turnTokenUsage.costUsd` when present across turns, else fall back to latest whole-session `contextWindow.cost` (Pi/OMP legacy), else reference pricing — NEVER sum whole-session `tokenUsage.cost` across multiple turns! (b) **Token input**: `TurnTokenUsage.inputTokens` ALREADY includes `cachedInputTokens + cacheCreationTokens`, so reference pricing computes `uncached = max(0, inputTokens - cachedInputTokens - cacheCreationTokens)` and total tokens = `inputTokens + outputTokens` (never adding `cachedInputTokens` twice). (c) **Subagent rollup**: if a subagent has BOTH `childThreadId` with loaded projection AND `subagent.usage`, prefer the richer child thread metrics and never double-count; when `otherUsage` is present on turns and per-subagent tokens are already accounted for, only add any positive residual or prefer per-subagent totals cleanly. (d) **Tool duration**: merge overlapping `[startedAt, completedAt]` intervals across parallel tool calls before computing `toolDurationMs` and `modelDurationMs = max(0, activeDurationMs - toolDurationMs)`. |
| **4. Persisted UI toggle compatibility**                                     | `hudOptionsStore.ts` (`t3lab:hud-ui:v1`) adds `showComposerRing: true` via `readBooleanOption`, so existing saved localStorage objects automatically default `showComposerRing` to `true`, `isDefaultHudUiOptions` includes `showComposerRing`, and `resetHudOptions` restores it cleanly. Corrupt JSON falls back to defaults.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                   |

## 4. Architecture & Export Discipline (`knip:check:exports`)

### Public Exports (consumed across modules)

- `packages/contracts/src/orchestrationV2.ts`: `OrchestrationV2SubagentUsage` (type + schema).
- `packages/shared/src/modelReferencePricing.ts` (`@t3tools/shared/modelReferencePricing`): `estimateModelReferenceCost`, `type ReferenceCostEstimate`, `type ReferenceCostTokenCounts`.
- `apps/web/src/fork/hud/hudOptionsStore.ts`: extend `HudCardVisibilityKey` with `"showComposerRing"` and `HudUiOptions` with `showComposerRing: boolean`.
- `apps/web/src/fork/hud/hudMetrics.logic.ts`:
  - `deriveSessionTelemetryMetrics`, `deriveComposerContextBreakdown`, `mergeIntervalsDurationMs` (keep internal helpers private; export only functions/types consumed by `ComposerTelemetryControl.tsx`, `HudSessionCard.tsx`, or `HudContextCard.tsx`!).
- `apps/web/src/fork/telemetry/ComposerTelemetryControl.tsx`: `ComposerTelemetryControl`.

### Module-Internal Helpers (NOT exported)

- Pricing alias resolver, slug normalizer, built-in rate table inside `modelReferencePricing.ts`.
- Subagent usage parsers/mergers inside `orchestration.ts`, `provider-pi/adapter.ts`, and `ClaudeAdapterV2.ts`.
- Interval merging helper (if only consumed inside `hudMetrics.logic.ts`, keep unexported and test through `deriveSessionTelemetryMetrics`!).
- Ring SVG leaf, segmented bar leaf, and tab sub-views inside `ComposerTelemetryControl.tsx`.

## 5. Performance & Visual Quality Invariants

- **Closed-state zero bloat**: When the popover is closed, ONLY the lightweight ring button renders. Child-thread projections for app-owned subagents and full `turnItems` breakdown scans are evaluated **inside the lazy-mounted popover content component** (only while `open === true`).
- **No continuous GPU animations**: Static SVG `stroke-dashoffset` ring and static flex segments; live ticking uses existing shared `secondTick` subscription isolated inside leaf components only while a turn is actively running AND the popover is open.
- **No Base UI nested popover conflicts**: The composer ring popover is a top-level composer footer `<Popover>` (sibling to `<ComposerModelPicker>`, respecting `composerMenusClosed` so switching threads or opening Settings closes it cleanly).
- **Zero raw Tailwind colors & zero middle-dot separators**: Use only declared semantic tokens from `apps/web/src/index.css` (`bg-info`, `bg-guest`, `bg-warning`, `bg-update`, `bg-primary`, `bg-success`, `bg-error`, `bg-muted`), no native `title` tooltips, and never use `·` as a separator in telemetry labels.
